CORE CONCEPTS

Sample Space & Events

Sample Space (Ω)

The set of all possible outcomes of an experiment or random process. Every outcome is unique, and together they cover everything that can happen.

In short: The "universe" of what could happen.

Event (E)

A subset of the sample space — one or more outcomes grouped together. Events can be simple (single outcome) or compound (multiple outcomes).

In short: A "collection" of outcomes you care about.

Probability P(E)

A number between 0 and 1 that measures how likely an event is to occur. 0 = impossible, 1 = certain, 0.5 = even chance.

Formula: P(E) = (favorable outcomes) / (total outcomes)

Complement (Ā or Ac)

Everything not in A. If A is an event, Ā is the opposite event — all outcomes where A does not occur.

Rule: P(Ā) = 1 − P(A)

CORE CONCEPTS

Set Operations & Event Types

Union (A ∪ B)

All outcomes that belong to A or B (including both). Think of it as "combining" both events.

Intersection (A ∩ B)

Outcomes that belong to both A and B. The overlap between two events.

Mutually Exclusive

A ∩ B = ∅. Events that cannot happen at the same time. Example: rolling a 2 and a 5 on one die.

Exhaustive Events

A ∪ B ∪ C ∪ … = Ω. A set of events that cover all possible outcomes. At least one must occur.

Independent Events

P(A∩B) = P(A)×P(B). The occurrence of one event does not affect the probability of the other.

De Morgan's Laws

The complement of a union = intersection of complements, and vice versa.

RULES

Rules of Probability

1. Unit Measure

P(Ω) = 1

2. Sigma-Additivity

P(∪Eᵢ) = Σ P(Eᵢ)

3. Complement

P(Ā) = 1 − P(A)

4. Union (Inclusion–Exclusion)

P(A∪B) = P(A)+P(B)−P(A∩B)

5. Conditional

P(A|B) = P(A∩B) / P(B)

6. Multiplication

P(A∩B) = P(A|B)×P(B)

7. Law of Total Prob.

P(A) = Σ P(A|Bᵢ)×P(Bᵢ)

8. Bayes' Rule

P(B|A) = P(A|B)×P(B)/P(A)
EXAMPLE

Microservices Architecture Failure Analysis

Scenario

A microservices application has 3 independent services: Auth, Database, and API Gateway. Each can fail independently during peak load:

  • • Auth fails: P(A) = 0.05
  • • Database fails: P(D) = 0.03
  • • API Gateway fails: P(G) = 0.02

The app crashes if all 3 fail. It's degraded if exactly 2 fail.

Solution

(a) P(app crashes) — all 3 fail together

= 0.05 × 0.03 × 0.02 = 0.00003

Uses: Multiplication Rule (independence)

(b) P(fully operational) — all 3 work

= 1 − 0.00003 = 0.99997

Uses: Complement Rule

Crash: 0.003%  |  Operational: 99.997%

(c) P(app degraded — exactly 2 fail)

3 possible combinations:

  • Auth + DB down, Gateway up: 0.05×0.03×0.98 = 0.00147
  • Auth + Gateway down, DB up: 0.05×0.97×0.02 = 0.00097
  • DB + Gateway down, Auth up: 0.95×0.03×0.02 = 0.00057
Total = 0.00147 + 0.00097 + 0.00057 = 0.00301

Computer Science Relevance

  • Cloud Computing — Estimating downtime for SLA guarantees
  • Distributed Systems — Redundancy planning for fault tolerance
  • DevOps — Calculating required replicas for 99.99% uptime
  • Network Engineering — Reliability of multi-path routing

🔐 Password Strength Estimator

Scenario: A system generates 4-digit PINs (0000–9999) for user accounts. An attacker guesses randomly.

1 How many possible PINs are there?

Hint: Each digit is 0–9

2 If the attacker tries 1 PIN per second for 1 hour, what's P(no success)?

Hint: Uses complement + multiplication

3 What's P(at least one success in 1 hour)?

Hint: Complement of Q2

4 How many hours to reach 90% success probability?

Hint: Solve 1 − (9999/10000)t = 0.9

SOLUTION 1

🔐 Password Strength — Answer

1. Total possible PINs

= 10 × 10 × 10 × 10 = 10,000

Uses: Counting principle

2. P(no success in 3600 tries)

= (9999/10000)3600 ≈ 0.6977

Uses: Multiplication (independence)

3. P(at least one success)

= 1 − 0.6977 = 0.3023

Uses: Complement rule

4. Hours for 90% success

t = ln(0.1)/ln(9999/10000) ≈ 23,025 tries ≈ 6.4 hrs
A 4-digit PIN is weak — only ~30% success in 1 hour!

🐛 Bug Detection in Code Review

Scenario: A code review tool detects bugs with 90% accuracy. Only 8% of code submissions actually contain bugs.

1 What's P(tool flags a bug)?

Hint: Law of Total Probability

2 If flagged, P(actual bug)?

Hint: Bayes' Rule

3 If not flagged, P(no bug)?

Hint: Bayes' Rule again

4 If 2 submissions flagged independently, P(both have bugs)?

Hint: Multiplication Rule

SOLUTION 2

🐛 Bug Detection — Answer

1. P(tool flags)

= 0.90×0.08 + 0.10×0.92 = 0.164

Law of Total Probability

2. P(bug | flagged)

= (0.90×0.08) / 0.164 ≈ 0.439

Bayes' Rule — only ~44%!

3. P(no bug | not flagged)

= (0.92×0.90) / 0.836 ≈ 0.991

High confidence when clean

4. P(both have bugs)

= 0.439 × 0.439 ≈ 0.193

Independence assumption

Key insight: Even a 90% accurate tool gives only 44% confidence — base rate matters!

📋 Network Security Risk Assessment

Scenario: A company's network has 3 independent defense layers: Firewall (F), Intrusion Detection System (IDS), and Antivirus (AV). Historical data:

P(F blocks) = 0.90 P(IDS detects) = 0.85 P(AV catches) = 0.75

A threat slips through if all 3 layers fail. Each layer is independent.

1 Sample Space: How many possible combinations of layer outcomes (block/detect/fail) exist?

Covers: Counting principle

2 Union: What's P(at least one layer catches the threat)?

Covers: Complement rule

3 Intersection: What's P(all 3 layers catch the threat)?

Covers: Multiplication rule (independence)

4 Conditional: Given IDS failed, P(Firewall also failed)?

Covers: Conditional probability + independence

5 Bayes: If the threat got through, P(Firewall was the only one that failed)?

Covers: Bayes' Rule + critical thinking

6 Challenge: The company adds a 4th layer. What minimum P(block) must it have to achieve 99.99% protection?

Covers: Solving for unknown probability

ASSIGNMENT SOLUTION

📋 Network Security — Answer Key

1. Sample Space Size

2³ = 8 possible outcome combinations

Each of 3 layers: 2 outcomes (success/fail)

2. P(at least one catches)

1 − (0.10×0.15×0.25) = 1 − 0.00375 = 0.99625

Complement: 1 − P(all fail)

3. P(all 3 catch)

0.90 × 0.85 × 0.75 = 0.57375

Multiplication rule (independence)

4. P(F failed | IDS failed)

P(F failed) = 0.10 (independent)

Independent → P(F) = 0.10 regardless

5. Bayes — Only Firewall failed given threat got through

= (0.10×0.85×0.75) / 0.00375 = 0.06375/0.00375 = 17

EDA: F failed, IDS+AV succeeded / P(all fail)

6. 4th layer for 99.99%

1 − (0.10×0.15×0.25×(1−p)) = 0.9999 → p = 0.7333

New layer needs ≥ 73.33% detection

Current protection: 99.625% — adding a 4th layer with ~73% gives 99.99%
